# EG Voice: перенос P0 в приложение и карта готовности MVP

Обновлено: 26 сентября 2026. Это статус настоящего React/TypeScript-приложения, не Design Lab. Наличие экрана в Design Lab не означает, что соответствующий сервис, нативная функция или backend уже реализованы.

## Что перенесено

### Голосовая сессия

- Один `VoiceProvider` над роутами. Переход в настройки и чат не уничтожает комнату.
- Настройки режима, порога, устройства и обработки хранятся локально и общие для настроек и панели звонка.
- После перезагрузки окна настройки восстанавливаются, но автоматического входа в звонок и открытия микрофона нет.
- При выходе из аккаунта провайдер уничтожается, захват и воспроизведение закрываются.
- Отмена подключения делает устаревшие результаты запроса токена / разрешения микрофона неактивными. Поздно полученные треки останавливаются.

### Реальная передача звука

Поток: `getUserMedia → AudioWorklet → MediaStreamDestination → LiveKit LocalAudioTrack → WebRTC`.

- **Голосовая активация:** порог −80…−10 дБFS, удержание конца фразы 0…1000 мс. Это энергетический порог, не распознавание человеческой речи. Громкая клавиатура тоже может открыть передачу.
- **Всегда включён:** передача без порога и без необходимости нажимать кнопку.
- **По кнопке:** V с удержанием или переключением. Есть экранная кнопка с pointer/keyboard-обработчиками.
- **Приоритет:** ручной mute, deafen, потеря устройства и переподключение закрывают передачу независимо от режима.
- **Защита PTT:** повтор keydown игнорируется; потеря фокуса, скрытие окна и смена режима сбрасывают передачу. Команды не срабатывают в полях ввода.
- **Глобальные клавиши:** пока НЕ реализованы. V работает в активном окне. Это честно подписано в настройках, вместо обещания работы поверх игры.
- **Обработка:** реальные WebRTC echoCancellation, noiseSuppression, autoGainControl. RNNoise, «Киберспорт ~5 мс» и «Качество ~40 мс» не выдаются за существующие функции.
- **Вывод:** системное устройство ОС. Выбор отдельного audio sink и индивидуальная громкость участников ещё не перенесены.

### «Тебя не слышно»

В подключённом звонке, вне PTT и не при mute/deafen, измеряется входной сигнал до программного порога передачи. Если уровень почти нулевой, ниже −75 дБFS, непрерывно 30 секунд, появляется предупреждение.

Текст не утверждает, что другой человек точно не слышит пользователя: причиной может быть обычная тишина. Есть «Я просто молчу» с паузой предупреждения на 5 минут и переход к реальным устройствам. При появлении сигнала предупреждение исчезает.

Это НЕ автоматическая диагностика сетевого пути до уха собеседника, НЕ распознавание речи при mute и НЕ определение причины тишины. Такие функции требуют дополнительных измерений и тестов.

### Соседние P0-кейсы

- Только реальные названия микрофонов из `enumerateDevices`; до разрешения нет выдуманных моделей.
- Отказ в разрешении или ошибка публикации сохраняет подключённую комнату в режиме слушателя. Повторная попытка не требует выходить из комнаты.
- При отключении гарнитуры передача закрывается. Новый вход выбирается явно; автоматической смены на потенциально приватный микрофон нет.
- При reconnect микрофон закрыт; после восстановления применяется текущий режим, PTT остаётся сброшенным.
- Запрет автопроигрывания показывает кнопку явного возобновления.
- Deafen влияет на уже существующие и вновь подписанные удалённые треки; после снятия deafen прежний ручной mute не теряется.
- Ошибка загрузки серверов или сообщений не показывается как пустой список.
- Черновик хранится отдельно для каждого пользователя и канала в текущей вкладке. Ошибка отправки его не очищает; во время отправки поле заблокировано от редактирования. Лимит 2000 символов проверяется и на сервере.
- Сетевая ошибка `/auth/me` не удаляет токен; есть явная повторная попытка. 401 защищённого API завершает сессию.
- Принятие приглашения обновляет список серверов до перехода на главную.
- Приглашения: лимит 10 участников, проверка последнего свободного места и расходования инвайта в одной SQLite-транзакции, повторное принятие идемпотентно.
- Создание канала только владельцем, одинаковое имя внутри одного типа канала отклоняется, числовые параметры инвайта только целые.
- Удалены встроенные ключи LiveKit из новой версии серверного исходника. Тела API-ответов, включая токены и сообщения, больше не пишутся в обычные access-логи.

## Полная карта оставшихся MVP-кейсов

Статусы: **реализовано** означает наличие кода, **частично** означает ограниченную реализацию, **нужно** означает следующий обязательный слой работы. Эта карта не объявляет продукт полностью готовым.

| Область | Кейсы и правило поведения | Статус |
|---|---|---|
| Вход | Пустые/некорректные данные, неверный пароль, повторная отправка | Базовая форма есть; расширенный аудит ошибок нужен |
| Регистрация | Пароль минимум 8, nickname/email, серверные ограничения | Реализованы базовые проверки |
| Защита входа | Rate limit по IP/аккаунту, lockout без утечки существования email, очистка попыток | Нужно до публичного запуска |
| Сессия | Нет интернета не равно «разлогинен», retry; 401 закрывает голос | Реализовано |
| Возврат после 401 | Предложить вернуться в канал без автоматического открытия микрофона, сохранить маршрут | Нужно |
| Восстановление | Отправка кода, срок, лимит повторов, неверный код, смена пароля | Только Design Lab; email/SMS backend нет |
| Телефон | Маска и подтверждение номера | Только Design Lab; не добавлять фиктивную SMS-авторизацию в релиз |
| Первое подключение | Безопасный контекст HTTPS, отсутствие WebAudio, ожидание разрешения, отмена | Обрабатывается отказ/ошибка и отмена; Windows WebView2 ещё не проверен |
| Устройства | Нет микрофона, запрет ОС, занят, неверный deviceId, unplug/replug | Реализованы сообщения, явный выбор и retry; физические гарнитуры нужно проверить |
| Bluetooth | Смена профиля, деградация качества, подключение во время звонка | Нужно проверить на Windows |
| Несколько вкладок | Один аккаунт в двух комнатах/вкладках, перенос звонка по согласию | Только макет; нет межвкладочного арбитража |
| Режимы | VAD/open/PTT hold/toggle, смена в звонке, сохранение | Реализовано и проверено |
| Mute/deafen | Ручной mute старше режима, снятие deafen не открывает ранее заглушённый микрофон | Реализовано и проверено |
| Тишина | 30 секунд почти нулевого входа, не при mute/deafen/PTT, не при reconnect | Реализовано; порог требует подстройки на реальных устройствах |
| Шум и клиппинг | Эхо, перегруз, распознавание «говоришь с выключенным микрофоном» | UI-макеты; автоматических детекторов нет |
| Шумодав | Системный WebRTC vs отдельный RNNoise, качество/задержка/CPU | Базовый WebRTC есть; RNNoise и FPS-бенчмарк нужны |
| Подключение | Запрос токена, cancel, истёкший токен, запрещённый канал | Базовый путь, ошибки API и отмена есть; UX детализация этапов нужна |

| Переподключение | Закрыть отправку, сохранить ручной mute, не реанимировать PTT | Реализовано; реальный обрыв сети/смена Wi-Fi требует внешнего теста |

| Модерация | Исключение участника, отзыв room-token, передача владельца | Пока Design Lab; серверной реализации нет |
| Черновики | Смена канала/настроек, отказ storage, ошибка отправки | Per-channel sessionStorage есть; при запрете storage только текущая память |

| Offline очередь | Набрать текст без сети, явный retry после восстановления | Черновик остаётся; автоматической очереди отправки нет |
| История | Подгрузка старых сообщений, не прыгать вниз при чтении, новые сообщения | Нужна отдельная итерация |
| Чат P1 | Ответ, редактирование, реакции, @, вложения и лимиты | Только Design Lab |

| РФ/Selectel | DNS, TLS, WSS, UDP/TURN, два разных провайдера без VPN | В этой итерации не развёрнуто и не проверено |

## Граница текущего выпуска

Исходники изменены и веб-сборка собрана. Это ещё не новый установленный `.exe`, не GitHub Release и не завершённый переезд на Selectel. Локальный WebRTC-тест не доказывает доступность голоса из РФ.

Прикреплённое превью использует отдельную тестовую базу: можно создать тестовый аккаунт для проверки интерфейса. В нём не настроен внешний голосовой сервер, поэтому попытка голосового подключения честно показывает 503, а не имитирует разговор. Если встроенное окно запрещает storage, авторизация, настройки и черновики сохраняются в памяти текущего окна; после его перезагрузки они могут сброситься. Исходная production-версия использует постоянное хранилище там, где браузер его разрешает.

Для настоящего голосового сервера нужны серверные переменные `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`; без них API отвечает 503 с объяснением. Для production также обязателен `JWT_SECRET`. В новой версии нет встроенного секрета LiveKit. Старые ключи, ранее попавшие в исходники/переписку, следует отозвать; удаление строки из нового файла не отзывает ключ автоматически.

Порядок следующего этапа: готовый Selectel/TURN → серверные credentials → новый Windows build → тест 2–3 друзей на разных сетях → тест 10 участников и FPS. До этого не обещаем «голос без VPN» и «без потери FPS» как проверенный результат.

## Как повторить проверки

```sh
npm ci
npx playwright install chromium
npm run check
npm run test:voice
npm run build
```

Для UI-автотестов запусти `npm run dev:voice-qa` в отдельном терминале, затем `npm run test:voice-ui`. Этот стенд использует транспортный адаптер только из `tests/vite.config.ts`; обычная сборка его не импортирует.

Для настоящего WebRTC-теста нужен локальный LiveKit. Официальный режим разработки и его тестовые credentials описаны в [документации LiveKit](https://docs.livekit.io/transport/self-hosting/local/). Они допустимы только на локальном стенде, не в production.

```sh
# Терминал 1
livekit-server --dev --bind 127.0.0.1

# Терминал 2: отдельная тестовая БД, не рабочая база
JWT_SECRET="$(openssl rand -hex 32)" DATA_DIR=./test-data \
LIVEKIT_URL=ws://127.0.0.1:7880 LIVEKIT_API_KEY=devkey LIVEKIT_API_SECRET=secret npm start

# Терминал 3
npm run test:voice-live
npm run test:mvp-api
```

API/RTC-тесты создают тестовые аккаунты и серверы: запускай их только на отдельной БД. В Windows переменные окружения задаются средствами PowerShell, а не POSIX-строкой выше.

В текущем окружении сборка прошла на Node 20.20.1, но npm сообщил, что транзитивный `machina@7.0.1` требует Node ≥22.22. Dockerfile и Windows CI переключены на ветку Node 22; CI дополнен typecheck и тестами голосовой политики. Сам Docker image и Windows job здесь не запускались. Есть предупреждение о крупном JS-bundle и PostCSS `from`; ошибок сборки нет, оптимизация загрузки остаётся отдельной задачей.
